# 播客后期分发助手 · 用户场景与流程 v0.1

## 一、用户场景细分

同是「独立播客主」，四种典型场景对产品的要求不同：

### 场景 A：单人口播主
- **画像**：一个人对着麦讲 20-60 分钟，无嘉宾。自我成长/影评/行业观察类居多，周更或双周更
- **特点**：不需要说话人分离；内容结构靠讲稿或即兴，章节划分价值大；最痛的是标题和宣传（没有嘉宾话题借力，全靠内容本身出圈）
- **对产品的要求**：跳过说话人标注步骤；金句卡片和切片是刚需（单人内容更依赖"亮点外露"获客）

### 场景 B：对谈/访谈档（主流场景，优先服务）
- **画像**：主播 + 搭档或嘉宾，60-150 分钟。录完最累：谁说了什么要区分，嘉宾介绍要写，提到的书/作品要整理
- **特点**：说话人分离必须准；shownotes 里「嘉宾介绍 + 提及内容清单」是标配；出彩片段常在观点交锋处
- **对产品的要求**：说话人重命名要顺手；上传时能填嘉宾名字和头衔；切片选段要识别"对话张力"而不只是金句

### 场景 C：回溯宣传（对已发布的旧集做切片）
- **画像**：节目发了没水花，或某期突然被算法推了，想趁热做切片二次传播
- **特点**：音频已在小宇宙/RSS 上，用户不想再找本地文件；只要切片和宣传笔记，不要 shownotes（已有）
- **对产品的要求**：支持粘贴 RSS/单集链接直接拉取音频；生成项可选（只勾选切片+宣传笔记）

### 场景 D：赶发布（时间压力型）
- **画像**：固定周四晚发布，周四下午才剪完。只要最快拿到标题 + shownotes 上架，宣传物料明天再说
- **特点**：对处理时长极其敏感；愿意牺牲切片换速度
- **对产品的要求**：转写完成后分批出结果（文本类先出，切片后台继续跑）；处理时间要有预估且可信

**MVP 取舍**：主服务 B，兼容 A（自动检测单说话人则隐藏相关步骤）；C 的链接拉取做（技术成本低、使用频率高）；D 通过「分批出结果」自然满足，不做单独模式。

## 二、核心动线：一期节目的完整生命周期

以场景 B 为例，从录完到发布的真实时间线：

```
周二晚 22:00  剪完音频，导出 mp3（90min，~90MB）
      22:05  打开工具 → 上传 → 填节目信息（2 分钟）→ 关掉页面去睡觉
      22:25  转写完成，系统开始生成物料（用户不在场）
      22:30  全部物料就绪，发通知（邮件/微信推送）
周三早 09:00  用户回来 → 工作台校对编辑（15-20 分钟）→ 复制发布
      09:30  在小宇宙后台粘贴 shownotes、定标题、上架
周三晚/周四   把金句卡片 + 切片发小红书/朋友圈/即刻
```

**动线核心洞察**：处理耗时 20-30 分钟，用户不会盯着等 → 「离开再回来」是常态，异步通知不是加分项而是主动线的一环；编辑校对是第二个主要停留点，工作台体验决定留存。

## 三、流程详设

### 流程 1：首次使用

【已拍板】进来即注册，手机号 + 验证码，一步完成，不做匿名试用。

1. **落地页**：一句话价值主张 + 一个 demo 示例（预置一期节目的完整物料包，可点看，不注册也能看 demo）+「开始使用」
2. 点开始使用 → 注册（MVP：邮箱验证码；后续加手机号）→ 直接进上传页
3. 上传中页面同步填写节目信息（利用等待时间，见流程 2 第 2 步）
4. 通知触达：MVP 处理完成发邮件；接手机号后升级为短信，App 版为 push

### 流程 2：核心流程——新一期节目

**Step 1 上传**
- 入口：拖拽/选择文件（mp3/m4a/wav/aac，≤3h、≤500MB），或粘贴 RSS/小宇宙单集链接
- 上传采用分片+断点续传（大文件在弱网下必挂，这是基础体验不是优化项）
- 上传中即开始 Step 2，不让用户干等

**Step 2 节目信息（上传期间并行填写，全部可跳过）**
- 节目名（有账号则记住，下次预填）
- 本期主题一句话
- 说话人：几个人、各叫什么（如"Yi / 嘉宾王老师-心理咨询师"）——直接决定转写标注和嘉宾介绍质量
- 本期想突出的点（可选，喂给标题和选段的 prompt）
- 生成项勾选：默认全选，可去掉不要的（场景 C 用户只勾切片+宣传笔记）

**Step 3 处理中**
- 阶段进度：上传 ✓ → 转写中（预估 X 分钟，按音频时长动态估）→ 生成物料中
- 转写完成即先开放逐字稿查看（场景 D 用户可以先开始干活）
- 文本类物料（章节/标题/shownotes/金句）先就绪先展示；切片最后
- 页面可关闭，完成后短信通知（注册手机号；App 版换 push）

**Step 4 工作台校对（用户主要停留点，预期 15-20 分钟）**

进入时默认展示「物料包总览」，按发布动作排序：标题 → shownotes → 章节 → 金句 → 切片。

- **逐字稿区（左侧）**：按说话人分色，点任意句子从该时间点试听；说话人重命名一次全局生效；支持文本修正（错别字、专有名词）
- **联动规则（关键细节）**：修正逐字稿后，已生成物料不自动重跑（避免覆盖用户编辑），但相关物料标记"逐字稿已更新，建议重新生成"，由用户决定
- **每个生成项**：直接编辑 / 重新生成（可带一句话指令："更口语""突出嘉宾观点"）/ 一键复制。重roll 保留上一版本，可回退
- **标题**：5 个风格标签（悬念/干货/情绪/提问/金句引用），点选即定稿
- **Shownotes**：结构分块（简介/章节/提及清单/嘉宾介绍），块级编辑和重roll；「提及清单」每项可删（AI 抽取会有噪音）
- **金句卡片**：先选金句（AI 给 5 条，可自己从逐字稿划选替换）→ 选 3 套模板之一 → 自动带节目名和期数 → 下载 PNG
- **切片**：每个候选片段展示：波形 + 高亮区间 + AI 推荐理由（"此处双方观点交锋"）+ 推荐文案。可拖动微调起止点（吸附到句子边界）→ 试听 → 下载 mp3 + 复制文案
- **顶部「复制发布包」**：按小宇宙格式拼装（简介+章节+提及+嘉宾），一键复制纯文本

**Step 5 发布（产品外，手动）**
- 用户去小宇宙后台粘贴。MVP 不做任何平台对接
- 发布后回来标记「已发布」（轻量闭环，为 V2 数据复盘留钩子）

### 流程 3：回溯宣传（场景 C）

1. 粘贴小宇宙单集链接或 RSS → 解析出音频 URL 和已有标题/shownotes
2. 生成项默认只勾：金句卡片 + 切片 + 小红书笔记
3. 已有 shownotes 作为上下文喂给选段 prompt（提高选段准确度）
4. 其余同核心流程 Step 3-4

### 流程 4：历史与复用

- 历史列表：封面色块 + 标题 + 日期 + 状态（草稿/已发布）
- 点入回到工作台，所有物料和编辑记录保留
- 「再来一期」从历史带出节目名、说话人、标题风格偏好（V2 风格记忆的入口）

### 流程 5：异常与边界（每条都要有明确的用户出路）

| 异常 | 处理 |
|------|------|
| 格式不支持/文件损坏 | 上传前端校验即时报错，列出支持格式 |
| 超时长/超大小 | 提示上限；建议压缩为 mp3（给一行 ffmpeg 命令或推荐工具） |
| 上传中断 | 断点续传自动恢复；失败可重试不重新选文件 |
| 转写失败 | 自动重试 1 次 → 仍失败则通知用户并说明原因，该期不计额度 |
| 说话人识别错（张冠李戴） | 逐字稿里可对单句改说话人；批量"从此句起以下都是 X" |
| 某项物料生成失败 | 其他物料正常展示，失败项单独显示重试按钮，不阻塞整体 |
| 转写质量差（方言/底噪重） | 展示置信度提醒："本期识别质量偏低，建议先校对逐字稿再生成物料" |
| 链接解析失败（场景 C） | 降级引导：请上传音频文件 |
| 额度用完 | 明确展示用量与恢复时间/升级路径 |

### 免费额度（MVP 建议）

注册用户每月免费 4 期（覆盖周更）、单期 ≤3h。MVP 阶段不收费，但额度体系从第一天就有——控成本，也为简历里"商业化设计"留故事。
