# 播客后期分发助手 · 功能设计 v0.2（MVP＝发布台）

对齐《01 产品定义 v0.2》《02 场景与流程》及已拍板决策：MVP 不做剪辑台（V1.5），上传的是成品音频；先做通用账号体系（手机号后续加）；邮件通知（短信后续换）；免费 4 期/月。

## 核心流程

```
注册（MVP：邮箱验证码，一步；手机号后续加）
   ↓
上传成品音频（分片断点续传）/ 粘贴 RSS·小宇宙单集链接
   ↓  （上传期间并行填写：节目名、本期主题、说话人名单、想突出的点、生成项勾选）
转写：阿里云百炼 Fun-ASR（说话人分离 + 句级/字级时间戳）
   ↓
AI 生成发布物料包（文本类先出，切片最后；完成发短信）：
   ├─ 标题备选 ×5（悬念/干货/情绪/提问/金句引用）
   ├─ 单集封面图（节目主视觉模板 ×3 版式）
   ├─ shownotes（简介/章节/提及清单/嘉宾介绍/固定尾部）
   ├─ 章节时间轴
   ├─ 金句卡片 ×3-5（1:1 + 3:4 两尺寸）
   ├─ 出彩切片 ×1-3（音频 mp3 + 推荐理由 + 配套文案）
   └─ 小红书宣传笔记（标题+正文+话题）
   ↓
发布台校对（checklist 驱动）→「复制发布包」→ 手动发小宇宙 → 标记已发布
```

## 页面结构（5 页）

1. **落地页**：价值主张 + 可点看的 demo 物料包 + 开始使用（→手机号注册）
2. **上传页**：文件/链接入口 + 节目信息表单（全可跳过）+ 生成项勾选（场景 C 只勾宣传类）
3. **处理中页**：分阶段进度 + 按时长动态预估 + 可关页（短信通知）+ 转写完先看逐字稿
4. **发布台**（核心，详设见《04》Stage 2）：左逐字稿（说话人分色/点句跳播/可修正/说话人重命名），右 7 个物料 Tab，顶部发布 checklist +「复制发布包」
5. **历史页**：往期列表（草稿/已发布）→ 回到发布台；「再来一期」预填节目信息

## 功能实现要点

| 功能 | 实现 | 关键细节 |
|------|------|----------|
| 注册/登录 | Supabase Auth 邮箱验证码（magic link/OTP） | 无密码；session 长效；账号表预留 phone 字段，后续加手机号登录只是多一种凭证 |
| 上传 | 分片+断点续传 → OSS | mp3/m4a/wav/aac，≤3h/≤500MB；前端即时校验 |
| 链接解析 | RSS/小宇宙单集页 → 音频 URL + 已有标题·shownotes 作上下文 | 解析失败降级为文件上传 |
| 转写 | Fun-ASR 非实时版（speaker_id + 时间戳） | 轮询+重试；识别置信度低时提示先校对 |
| 物料生成 | DeepSeek-V3 / Qwen-Max，全部结构化 JSON 输出 | 长稿分段+汇总；每项独立生成，单项失败单项重试；重roll 支持一句话指令并保留上一版 |
| 提及清单 | 单独实体抽取 prompt | 逐项可删可补链接 |
| 封面图 | 节目主视觉（一次设置：底图/主色/字体）+ 3 版式模板，前端 Canvas 渲染 | 输出 3000×3000；标题定稿自动同步；AI 生图背景 V1.5 |
| 金句卡片 | 复用主视觉系统 | AI 候选 5 条 + 逐字稿划选生成 |
| 切片 | **两级漏斗**：① 确定性预筛（转录稿信号：说话人切换密度/笑声/静音/问答对/句长突变）出 top15-20 候选 ② LLM 精选排序+理由+文案 → ffmpeg 切割 | 成本降一个数量级且更准（见 10 借鉴分析）；语轮边界吸附、问答成对、语轮完整度门槛；输出结构化 provenance 标签 |
| 通知 | 邮件（物料就绪/失败，Resend 等即可） | 接手机号后换短信；App 版换 push |
| 额度 | 4 期/月，用量与恢复时间可见 | 失败不计额度 |

联动规则（待最终确认）：逐字稿修正 → 物料不自动重跑，相关 Tab 标"建议刷新"；标题定稿 → 自动同步封面图与宣传笔记。

## 技术选型

- 前端：Next.js（App Router）+ Vercel
- 长任务（转写轮询/ffmpeg/卡片批量导出）：队列 + worker（Inngest/QStash 或轻量云主机）
- 存储/DB/Auth：Supabase + 阿里云 OSS（Fun-ASR 需公网可访问文件）
- 成本：90min 单期 ≈ 转写几元 + LLM 几毛

## 4 周里程碑

- **W1**：注册 + 上传（含断点续传）→ Fun-ASR 转写 → 逐字稿展示。用真实 90min 音频测全链路
- **W2**：文本物料四件套（标题/shownotes/章节/宣传笔记）+ 发布台雏形 + 用自己节目调 prompt
- **W3**：切片 + 金句卡片 + 封面图（主视觉设置+模板渲染）+ 编辑/重roll/复制发布包
- **W4**：checklist、历史页、邮件通知、额度、异常兜底（02 流程 5 的 9 条）→ 部署 → 自己发一期 → 找 3-5 个播客主试用

## 关键风险

1. 长音频链路稳定性（W1 就用真实文件测，不用短样本自欺）
2. 选段/章节质量——预留 prompt 迭代时间，交互兜底（推荐+手动微调）
3. 小宇宙无 API，发布靠复制——「复制发布包」把摩擦压到最低
4. （已规避）短信资质问题：MVP 改用邮箱账号+邮件通知，无资质门槛；后续加手机号时再处理短信签名申请
