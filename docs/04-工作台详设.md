# 播客后期分发助手 · 工作台详设 v0.1

> 【已拍板 2026-07-16】MVP 选方案 B：**剪辑台（Stage 1）整体推迟到 V1.5**，MVP 只做发布台（Stage 2，含封面图），上传的默认是已剪好的成品音频。本文 Stage 1 部分作为 V1.5 的设计存档。

工作台是用户停留最久、决定产品成败的地方。它分两个阶段：

```
Stage 1 剪辑台：raw 素材 → 流畅有逻辑的成品音频
Stage 2 发布台：成品音频 → 全套发布物料（标题/shownotes/章节/金句/切片/宣传笔记/封面图）
```

上传时询问素材类型：「原始录音/粗剪」进 Stage 1；「已剪好的成品」直接进 Stage 2。所有 Stage 2 物料基于**成品时间轴**生成（否则章节和切片的时间戳全是错的）。

---

## Stage 1 剪辑台

### 1.1 范式：文字即剪辑

- 逐字稿就是剪辑界面：**删一段文字 = 剪掉一段音频**。用户全程不碰波形轨道（想微调时才展开波形）
- **非破坏性**：所有删除只是标记，原始音频永远完整，任何删除随时恢复
- 这是 Descript 的范式，但 Descript 中文支持差、无中文语境的 AI 建议——这就是差异化空间

### 1.2 AI 剪辑建议：四层模型

AI 通读全稿后给出分层建议，每条建议 = `{类型, 起止时间, 理由, 置信度, 节省时长}`：

**L1 清理层（置信度高，可一键全收）**
- 填充词：嗯、啊、呃、就是说、然后然后、那个那个
- 长停顿（>2.5s，阈值可调）、口误重说（"我们上周——不对，上上周"保留后者）
- 假开头/重录段：识别"我重来一遍"类信号，删掉废弃的前几遍
- 设备杂音明显段（咳嗽、桌子碰撞，靠 ASR 置信度骤降检测，尽力而为）

**L2 内容层（AI 判断，逐条过）**
- 冗余表达：同一观点换着说了三遍，保留最完整的一遍
- 跑题段落：与主线无关的闲聊支线（标记后给用户判断——有的跑题恰恰是节目魅力）
- 低信息密度段：开场寒暄、找词卡壳的空转
- 每条附理由："此段与 12:30 处观点重复，保留 12:30 版本更完整"

**L3 结构层（建议而非执行，V1.5）**
- 冷开场（cold open）建议：从全片挑最抓人的 20-40 秒，建议提到片头
- 段落重排：发现"更适合放在前面的论述"时提示（重排实现复杂，先只提示不执行）
- 缺转场提醒："此处话题跳转生硬，建议补录一句过渡口播"（给出建议台词）

**L4 风格层（全局参数，影响 L1-L3 的力度）**

上传时或剪辑台顶部选择成品风格：

| 风格 | 剪辑力度 | 典型效果 |
|------|----------|----------|
| 紧凑干货 | 激进：L1 全删 + L2 大部分采纳 | 90min → 55-65min，信息密度优先 |
| 松弛闲聊 | 保守：只删 L1 硬伤，保留语气停顿和跑题 | 90min → 80min，氛围优先 |
| 叙事精编 | 激进 + 结构层介入最多 | 适合故事类节目 |

风格还影响 Stage 2 所有文案的语气（标题、shownotes、宣传笔记一致）。

### 1.3 交互细节

- **建议的呈现**：逐字稿上直接标记——L1 灰色删除线、L2 黄色高亮块、L3 蓝色角标。右侧建议面板按层分组，显示"共 47 条建议，预计 90min → 63min"
- **处理动作**：单条 采纳/忽略；按层批量（"采纳全部 L1"是最高频操作，放显眼处）；采纳后仍可点删除线恢复
- **试听**：任意位置播放自动跳过已删段（无缝预览成品效果）；每条建议有"对比试听"（删前 vs 删后各 5 秒上下文）
- **手动剪辑**：划选文字 → 删除；剪切点默认吸附句子边界，展开波形可做字级微调
- **快捷键**：空格播放/暂停，D 删除选中，R 恢复，←→ 按句移动，Shift+A 采纳当前建议
- **自动保存 + 版本**：每次批量操作生成一个版本点，可回退
- **进度感**：顶部实时显示当前成品时长和已节省时长（给用户"在变好"的反馈）

### 1.4 确认剪辑 → 渲染

- 点「生成成品」：服务端按保留区间 ffmpeg 拼接，剪切点 15ms crossfade 防爆音，整体响度归一（loudnorm，播客标准 -16 LUFS）
- 渲染中即开始 Stage 2 物料生成（用剪辑后的文稿，不必等音频渲染完）
- 产出：成品 mp3 下载 + 时间戳全部重映射到成品时间轴
- 渲染后仍可回 Stage 1 改（改完需重渲染 + 提示物料时间戳需刷新）

### 1.5 明确不做的（守住边界）

多轨编辑、BGM/音效/片头片尾音乐混音、EQ/压缩等音效处理、降噪（建议用户先用 Adobe Podcast Enhance 免费处理再上传，产品内给引导链接）。这些是专业剪辑软件的地盘，做了就是和 Descript/剪映拼刺刀。

## Stage 2 发布台

### 2.1 整体布局

- 左侧：成品逐字稿（说话人分色、时间戳、点句跳播）——此时是只读参考，修正错别字仍可以
- 右侧：物料 Tab ×7：标题 / 封面图 / Shownotes / 章节 / 金句卡片 / 切片 / 宣传笔记
- 顶部：发布 checklist（每项物料 待处理/已确认 状态点，全部确认后「复制发布包」高亮）——给校对一个明确的"做完了"的终点

### 2.2 各模块细节

**标题**
- 5 备选 ×5 风格标签，点选定稿；可输入指令重roll（"要有数字""提嘉宾名字"）
- 定稿标题自动同步到封面图和宣传笔记

**封面图（新增，发布必需项）**
- 规格：1:1 方形，导出 3000×3000 PNG/JPG（兼容小宇宙和 Apple Podcasts 标准）
- **首次使用设置「节目主视觉」**：上传节目 logo/底图 + 选主色 + 选字体风格，之后每期自动套用，保证专辑页视觉统一——这是频道感的关键，也是留存钩子
- 每期生成：3 套版式模板（大字标题版 / 嘉宾名突出版 / 金句版），自动填入本期标题、期数、嘉宾名
- 可调：换底色、换背景图（上传 or AI 生图三选一）、字号自动适配换行
- 金句卡片复用同一套主视觉系统（节目品牌一致性）

**Shownotes**
- 分块：本期简介 / 时间轴章节 / 提及的书·影·人·链接 / 嘉宾介绍 / 固定尾部（订阅引导，节目级设置一次）
- 块级编辑与重roll；提及清单逐项可删可补链接
- 复制时可选格式：小宇宙纯文本 / Markdown / 通用 RSS HTML

**章节**
- `[mm:ss] 章节名` 列表，时间基于成品时间轴；点击试听该章节开头；可改名、合并、拆分

**金句卡片**
- AI 候选 5 条 + 用户可从逐字稿划选任意句子生成
- 套主视觉模板 → 批量导出 PNG（1:1 和 3:4 两种尺寸，适配朋友圈和小红书）

**切片**
- 候选 1-3 段，每段：波形高亮 + AI 推荐理由 + 起止微调（句边界吸附）+ 试听 + 下载 mp3 + 配套文案
- 切片文案与宣传笔记联动（笔记里引用切片内容）

**宣传笔记**
- 小红书风格：标题（≤20 字带 emoji）+ 正文（钩子开头 + 3 个看点 + 收听引导）+ 话题标签
- 风格跟随 L4 选择的节目风格

### 2.3 联动规则汇总

- 逐字稿修正 → 不自动重跑物料，相关 Tab 显示"建议刷新"标记，用户决定
- 标题定稿 → 自动更新封面图文字和宣传笔记（这两处是引用关系，非独立生成）
- 回 Stage 1 重剪 → 所有带时间戳的物料（章节/切片）标记失效，需一键刷新；纯文本物料（标题/金句文案）提示但不强制

## 状态机

```
uploaded → transcribing → suggesting(AI剪辑建议生成) → editing(用户剪辑中)
→ rendering(渲染成品) ⇄ material_generating → reviewing(校对中) → ready → published
```

任何生成类状态失败：单点重试，不回滚整体。

## 对排期的影响（必须直说）

剪辑台让工程量增加约 60%：ASR 字级时间戳对齐、建议引擎、非破坏性编辑状态管理、无缝预览播放器、服务端渲染，每个都不小。两个选择：

- **方案 A（推荐）**：MVP = L1+L2 建议 + 文字删除 + 渲染 + 发布台全套，L3 和封面图 AI 生图推后。排期 5-6 周
- **方案 B**：坚守 4 周，Stage 1 整体推到 V1.5，MVP 只做发布台（回到原范围）

我的看法：剪辑建议是这个产品从"文案工具"变成"后期工作台"的跃迁，简历故事也更硬（AI 建议引擎是有技术含量的 PM 故事），值得多花两周。
