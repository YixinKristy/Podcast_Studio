# 播客后期分发助手 · 链路闭环与异常策略 v1.0

逐链路枚举分岔与异常。原则：**每个分支都有明确出路，用户永远不会卡死在某个状态；失败不吞额度；系统状态可从任意中断点恢复。**

## A. 账号链路

| # | 分岔/异常 | 策略 |
|---|-----------|------|
| A1 | 验证码邮件未收到 | 60s 可重发；提示查垃圾箱；连续 3 次失败提示换邮箱并记录（排查发信域名问题） |
| A2 | 验证码输错 | 5 次锁 10 分钟，防爆破 |
| A3 | 会话过期时正在编辑 | 静默续期；失败弹登录框，**编辑现场本地暂存**，登录后恢复 |
| A4 | 多设备同时登录 | 允许；编辑冲突见 F1 |
| A5 | 注销账号 | 二次确认（输入邮箱确认）→ 删除音频/物料/账号；进行中的任务先取消；30 天冷静期内可撤销（软删除） |
| A6 | 注册后未建节目就关页 | 下次登录仍强制进 P1.5（节目名是后续一切的前提），不可绕过 |
| A7 | 从邮件深链进入但未登录 | 记住目标 /e/{id} → 登录后跳回，不落在首页（通知触达的闭环） |

## B. 建节目链路（P1.5）

| # | 分岔 | 策略 |
|---|------|------|
| B1 | 节目名想后改 | 设置页随时改；已生成的历史封面不追溯（见 K1） |
| B2 | 主视觉跳过未设 | 允许；发布台封面 Tab 显示引导卡，设置后本期立即可用 |
| B3 | 用户有多档节目 | MVP 单节目；「+新节目」置灰＋「联系我们开通」（手动放白名单，兼做需求验证） |

## C. 上传链路

| # | 分岔/异常 | 策略 |
|---|-----------|------|
| C1 | 文件格式/大小/时长不合规 | 选中即前端拦截；提示上限（**≤2h**，说话人分离限制）+ 压缩建议（ffmpeg 一行命令 + 推荐图形工具） |
| C12 | 立体声音频 | 服务端自动转单声道后送 ASR（说话人分离仅支持单声道），对用户无感；原始文件保留 |
| C2 | 文件损坏（能过格式校验但解码失败） | 转写前服务端探测（ffprobe）；失败提示「文件可能损坏，请重新导出」，不计额度 |
| C3 | 上传中断网/关页/关机 | 分片+断点续传；重进 /new 或历史页的「未完成」卡片可续传，不重选文件；**分片保留 24h**，超时清理 |
| C4 | 上传完但没点「开始生成」且关页 | 默认开关=上传完自动开始，此分支基本消失；若用户关掉了自动开始，episode 停在 uploaded 态，历史页显示「待开始」卡片＋一键开始；7 天未动邮件提醒一次 |
| C5 | 重复上传同一文件 | 秒传（hash 命中）＋提示「这期已存在，去查看？」，避免重复扣额度 |
| C6 | 同时上传两期 | 允许并发 2 个任务；第 3 个排队并明示 |
| C7 | 上传到一半额度被并发任务用完 | 额度在「开始生成」时才扣减并锁定；上传本身不扣。扣减采用事务，先到先得，后者拦截并提示 |
| C8 | 链接解析失败/音频 URL 拉取失败 | 即时提示 + 降级上传文件；解析成功但下载失败（防盗链）同样降级，文案区分 |
| C9 | 额度不足 | 上传页顶部拦截横幅：已用 4/4，X 月 X 日恢复；「导出往期物料不受影响」；付费升级入口占位 |
| C10 | 非音频内容（如上传了视频） | m4a/mp4 容器含视频轨时自动抽音频轨继续，提示「已提取音频」 |
| C11 | 上传他人节目链接 | 上传页勾选声明「我是该节目的创作者或已获授权」（默认勾选态不预勾），法务兜底 |

## D. 转写链路

| # | 分岔/异常 | 策略 |
|---|-----------|------|
| D1 | ASR 服务超时/报错 | 自动重试 1 次（间隔 1min）→ 仍败：episode 置 transcribe_failed，邮件+页面告知，一键重试，不计额度 |
| D2 | 轮询进程崩溃（worker 挂了） | 任务心跳；超 15min 无心跳自动重新入队；对用户无感 |
| D3 | 识别置信度整体偏低 | 发布台顶部黄条 + 定位到低置信段；物料照常生成但提示「建议校对后刷新」 |
| D4 | 完全无法识别（纯音乐/静音文件） | 有效语音占比 <10% → 终止流程，提示「没识别到足够的人声」，不计额度 |
| D5 | 实际说话人数 ≠ 嘉宾填写数 | 以 ASR 结果为准展示 N 个说话人；已填嘉宾名做自动匹配建议（按发言量排序），用户确认 |
| D6 | 单说话人节目 | 自动检测 → 逐字稿不显示说话人标签、发布台隐藏"嘉宾介绍"块（场景 A 适配） |
| D7 | 说话人串轨 | 单句改说话人＋「从此句起以下都是 X」批量改 |
| D8 | 中英夹杂/方言 | Fun-ASR 中英粤可覆盖；生僻方言归入 D3 低置信路径 |
| D9 | 超长静音段/音乐垫片 | 转写自动跳过；章节生成时把长音乐段作为天然章节边界候选 |
| D10 | 结果 URL 过期（24h）未下载 | 任务完成后立即下载 JSON 落库（与轮询同一原子步骤）；若确已过期则整单重跑转写，不扣额度 |
| D11 | 敏感词被打码成 `*` | 调用时显式 `system_reserved_filter: false` 关闭系统词表；spike 阶段必须验证关闭生效 |

## E. 物料生成链路

| # | 分岔/异常 | 策略 |
|---|-----------|------|
| E1 | 单项生成失败 | 该 Tab 失败卡＋单项重试；不阻塞其他项；连续失败 3 次转人工排查提示 |
| E2 | LLM 返回 JSON 格式坏 | 服务端 schema 校验 → 自动带错误信息重试 1 次 → 仍败走 E1 |
| E3 | LLM 内容安全拒答（敏感话题节目） | 该项显示「此内容无法自动生成」，逐字稿和其他项不受影响；文案不指责用户 |
| E4 | 长稿超上下文 | 分段摘要 → 汇总两级流水线（架构默认，非降级） |
| E5 | 切片无高置信候选 | **质量降级而非失败**：仍给出信号最强的 2-3 段并标注「低置信，建议自选」；同时提供逐字稿划选生成（用户兜底 AI）。原则：宁可降级产出并如实标注，不给空态 |
| E10 | 说话人分离失败 | 降级为无说话人标注模式，其余物料照常生成，仅隐藏嘉宾介绍块 |
| E6 | 章节过多/过少 | 约束 prompt（60-120min 目标 5-9 章）；超界自动二次合并/细分 |
| E7 | 金句抽取全是嘉宾没有主播（或反之） | prompt 要求说话人均衡采样；用户可划选补充 |
| E8 | 「宣传侧重」字段与内容明显无关（用户填错期） | 不做强校验；标题/笔记生成结果自然暴露，用户重roll 即可（不过度设计） |
| E9 | 生成中用户已开始编辑逐字稿 | 允许；生成完成时若逐字稿有 diff，相关 Tab 直接带「建议刷新」红点出生 |

## F. 发布台链路

| # | 分岔/异常 | 策略 |
|---|-----------|------|
| F1 | 两个标签页/设备同时编辑同一期 | 乐观锁：后保存者提示冲突，展示两版 diff 选择保留；MVP 可简化为「以最后保存为准＋toast 警告另一端」 |
| F2 | 逐字稿修正后的传播 | 不自动重跑；受影响 Tab 红点「逐字稿已更新，建议刷新」；点刷新=带新稿重roll，旧版本进版本历史 |
| F3 | 标题重选，但封面已被手动改过文字 | **不静默覆盖**：弹提示「封面文字是你手动改过的，要同步新标题吗？」（同步/保留） |
| F4 | 重roll 后不满意 | 版本历史保留 5 版，任意回退 |
| F5 | 未全部确认就复制发布包 | 允许，提示「还有 N 项未确认」；不阻塞（用户可能只发部分物料） |
| F6 | 复制发布包后又改了内容 | 「复制发布包」按钮旁出现「内容已变更，重新复制」角标 |
| F7 | 标记已发布后又要改 | 允许重新编辑；状态回「待校对」需二次确认（防误触），历史徽标同步 |
| F8 | 切片微调后与推荐文案不符 | 起止变动 >20% 时提示「片段已大改，文案要重新生成吗」 |
| F9 | 波形加载失败（长音频峰值计算慢） | 波形为渐进加载，失败降级为纯时间轴滑条，功能不受阻 |
| F10 | 音频试听加载慢 | HLS/Range 分段拉流，点击句子 2s 内出声为验收线 |

## G. 链接导入（场景 C）专属

| # | 分岔 | 策略 |
|---|------|------|
| G1 | RSS 含多集 | 列表让用户选一集（默认最新） |
| G2 | 已有 shownotes 抓取成功 | 作为上下文喂给选段/笔记 prompt；生成项默认只勾宣传三件套（可改） |
| G3 | 已发布节目再导入（历史里已存在同源） | 提示已存在，跳转旧工作台而非重复消耗额度 |

## H. 额度与生命周期

| # | 分岔 | 策略 |
|---|------|------|
| H1 | 扣减时点 | 「开始生成」时扣 1 期并锁定；转写失败(D1/D4)、文件损坏(C2) 自动冲正 |
| H2 | 月度重置 | 自然月 1 日重置；页面显示恢复日期 |
| H3 | 删除一期 | 释放存储；**不返还额度**（防刷）；二次确认并说明 |
| H4 | 原始音频保留策略 | 成品物料永久保留；原始音频保留 90 天后仅保留转写稿和切片成品（成本控制），提前 7 天邮件告知可下载 |
| H5 | 长期不活跃 | 不删数据（MVP 用户少成本可控）；只做 H4 的音频清理 |

## I. 通知链路

| # | 分岔 | 策略 |
|---|------|------|
| I1 | 完成邮件发送失败 | 重试 2 次；页面内状态永远是事实源，邮件只是提醒 |
| I2 | 用户没看到邮件 | 首封邮件后 toast 提示「记得查垃圾箱并加白名单」 |
| I3 | 邮件类型控制 | 仅事务性邮件（完成/失败/音频清理预告），一键退订营销类（MVP 无营销邮件） |

## J. 设置变更的传播规则（K 链路）

| # | 变更 | 传播 |
|---|------|------|
| K1 | 改节目名/主视觉/固定尾部 | 只影响**之后新生成**的物料；历史期不追溯。历史期发布台内提供「应用最新主视觉」手动按钮 |
| K2 | 改常驻说话人 | 只影响新一期的默认标注 |

## L. 全局资损/安全底线

- 所有写操作幂等（重试不产生重复物料/重复扣额度）
- 音频与物料仅本人可见；对象存储私有读，签名 URL 时效 1h
- 逐字稿含敏感个人信息的风险 → 隐私政策明示「音频仅用于为你生成物料，不用于训练」
- 成本熔断：单账号单日转写时长上限 6h（防脚本滥用），触发后人工审核解锁

## 状态机（修订版，覆盖以上所有分支）

```
draft(未完成上传，可续传/24h 过期)
 → uploaded(未开自动开始时停留，可一键开始/7 天提醒)
 → transcribing → transcribe_failed(重试, 冲正额度)
 → generating(逐项完成逐项 ready) → 单项 failed(单项重试)
 → ready(待校对) ⇄ published(可回退,二次确认)
任何状态：可删除(二次确认, 不返额度)
```
