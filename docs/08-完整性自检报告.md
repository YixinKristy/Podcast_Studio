# 播客后期分发助手 · 功能完整性自检报告 v1.0

方法：feature-design-completeness 六步法。对象归类 → 全生命周期触点清点 → 多视图 → 新/继承拆分 → 反向进入验证。

## 一、对象归类

系统里的核心对象与母概念：

| 对象 | 母概念 | 继承的契约 |
|------|--------|-----------|
| Episode（一期） | 内容记录 | 列表呈现、详情、删除、状态、搜索/筛选、导出、喂下游 |
| 7 种物料 | 生成型交付物 | 查看、编辑、重roll（带指令）、版本回退、确认、复制/下载、失败重试、"建议刷新"提示 |
| 逐字稿 | 内容资产（非生成型） | 查看、校对编辑、**导出**、喂下游 |
| 原始音频 | 用户资产 | 存储、试听、**下载**、清理策略 |
| 版本 | 历史记录 | 查看、回退、上限 |
| 邮件通知 | 触达 | 送达、**深链回跳**、退订 |
| 额度 | 账户资源 | 展示、扣减、冲正、**用量明细** |

## 三、多视图检查
- Episode：卡片列表够用；日历/时间线视图不适用 MVP
- ★文档内部不一致：PRD P4 写「进入时默认展示物料包总览」但 Tab 结构无总览页 → 修正措辞：默认落在标题 Tab，checklist 即总览
- ★PRD Tab2 缺 07-K1 承诺的「应用最新主视觉」按钮 → 补

## 四、新的 vs 继承的（注意力分配）
- 差异化（投创意）：宣传侧重字段 → 爆点选段 → 爆款笔记的链路；主视觉系统；风格三档
- 继承契约（投严谨，本次漏主要在这）：7 物料统一的 编辑/重roll/版本/确认/复制/重试/刷新 七件契约——上表已逐格对齐，开发时按契约矩阵实现为统一组件，禁止每个 Tab 各写一套

## 六、修正清单（已同步到 05/07）
**MVP 必修**：① 章节 Tab 补重roll；② 金句「换一批」；③ 标题重生成保留上一批；④ 逐字稿复制/导出 txt/md；⑤ 原始音频下载入口；⑥ 邮件深链回跳（07-A7）；⑦ 设置页额度明细；⑧ PRD 总览措辞修正；⑨ PRD Tab2 补「应用最新主视觉」
**V1.1**：历史页状态筛选；整期物料 zip 导出
**V1.5**：srt 字幕导出（随视频切片）

收口：七种物料是同一母概念的公民——权利（出现在 checklist、发布包、历史）与义务（七件契约）必须整齐划一；本次漏的全部是「继承」侧，差异化侧无漏，符合该 skill 预警的典型失败模式。
