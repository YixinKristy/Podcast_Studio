## 二、技术栈定稿

| 层 | 选型 | 理由 |
|----|------|------|
| 框架 | Next.js 15 App Router + TypeScript | 全栈一体，Vercel 部署顺 |
| UI | Tailwind + shadcn/ui | 组件齐、可控 |
| 状态 | Zustand（客户端）+ React Query（服务端态） | 发布台状态复杂，需要好用的缓存与乐观更新 |
| DB/Auth/Storage | Supabase（Postgres + Auth OTP + RLS） | 一站式，RLS 天然满足「仅本人可见」 |
| 音频存储 | 阿里云 OSS | Fun-ASR 要求公网可访问 |
| 队列/长任务 | Trigger.dev 或 自建 worker（见下） | Vercel serverless 超时限制，转写 20 分钟必须异步 |
| ASR | 阿里云百炼 Fun-ASR（非实时） | 中文+说话人分离+时间戳 |
| LLM | 百炼 Qwen（适配层可切 DeepSeek） | 结构化 JSON 输出 |
| 音频处理 | ffmpeg（worker 内） | 切片、格式探测 |
| 图片渲染 | 前端 Canvas（封面/金句卡） | 无服务端渲染成本 |
| 测试 | Vitest（单测）+ Playwright（E2E） | |
| CI | GitHub Actions | PR 必过 lint+typecheck+单测 |

**队列方案决策点**：优先 Trigger.dev（免费层够个人项目，省运维）；若其 ffmpeg 支持受限，退回「Railway/Fly.io 跑一个常驻 worker 容器」。W1 第一天做技术验证时定死。

## 三、仓库结构

```
podcast-studio/
├── app/
│   ├── (marketing)/          # P0 落地页
│   ├── (app)/
│   │   ├── onboarding/       # P1.5 建节目
│   │   ├── new/              # P2 上传
│   │   ├── e/[id]/           # P3 处理中 + P4 发布台（按状态渲染）
│   │   ├── episodes/         # P5 历史
│   │   └── settings/         # P6 设置
│   └── api/                  # 路由处理器（薄，只做鉴权+校验+调 service）
├── components/
│   ├── ui/                   # shadcn 基础件
│   ├── studio/               # 发布台：Transcript / MaterialTab / Checklist / Player / Waveform
│   └── material/             # ★ 七物料统一契约组件（08 自检要求）
├── lib/
│   ├── services/             # 业务逻辑（可单测，不依赖 HTTP）
│   │   ├── episode.ts        # 状态机
│   │   ├── quota.ts          # 额度扣减/冲正
│   │   ├── transcript.ts     # 时间戳/说话人
│   │   └── materials/        # 7 种生成器，共用 generator 基类
│   ├── ai/                   # LLM 适配层 + prompt 模板 + schema 校验
│   ├── asr/                  # Fun-ASR 客户端
│   ├── storage/              # OSS
│   └── db/                   # Supabase 客户端 + 类型
├── jobs/                     # 异步任务：transcribe / generate / clip
├── prompts/                  # ★ prompt 独立成文件，可版本化、可 diff、可 A/B
├── tests/
│   ├── unit/
│   ├── fixtures/             # 真实转写稿样本（脱敏），prompt 回归测试用
│   └── e2e/
└── docs/                     # 软链或复制 01-08 产品文档
```

**关键架构约束（防返工）**：
1. **API 路由保持薄**：业务逻辑全在 `lib/services`，纯函数优先——这是能写单测的前提
2. **物料生成器统一基类**：七种物料共享 `generate/regenerate(instruction)/validate/version` 接口，对应 08 自检的七件契约
3. **prompt 与代码分离**：放 `prompts/*.ts`，改 prompt 不改逻辑，方便迭代和回归
4. **时间戳单一来源**：所有物料的时间戳都从 transcript segments 派生，禁止各自计算

## 四、开发规范

### 分支与提交
- `main` 保护，功能走 `feat/xxx` 分支 → PR → CI 绿 → 合并
- Conventional Commits：`feat: / fix: / test: / refactor: / chore:`
- 每个 PR 对应一个可验收的功能点，附「怎么验」的说明（Yi review 用）

### 代码规范
- TypeScript strict + ESLint + Prettier，CI 卡死
- 禁止 `any`（确需时 `unknown` + 类型守卫）
- 所有外部 API 响应过 zod schema 校验（LLM 输出尤其重要，对应 07-E2）
- 所有写操作幂等（对应 07-L）
- 错误处理：service 层抛类型化错误 → API 层映射为用户可读文案（07 里的每条异常都有对应文案）

### 环境与密钥
- `.env.local` 不入库；`.env.example` 入库列出所有 key
- Supabase RLS 从第一张表就开启，不留「以后再加」

## 五、测试策略（分层务实）

| 层 | 范围 | 工具 | 门禁 |
|----|------|------|------|
| 单测 | **必测**：额度扣减与冲正（07-H1）、状态机流转（07 状态机）、时间戳映射与章节边界、LLM 输出 schema 校验与坏数据重试、发布包拼装格式、切片起止边界吸附 | Vitest | PR 必过 |
| 集成 | ASR 客户端（录制真实响应做 fixture）、OSS 上传、Supabase RLS（越权读取必须失败） | Vitest + 本地 Supabase | PR 必过 |
| E2E | 主流程一条：注册 → 建节目 → 上传短音频 → 转写 → 生成 → 编辑 → 复制发布包；异常一条：转写失败 → 重试 → 额度未被吞 | Playwright | 合并前跑 |
| Prompt 回归（★升级） | 3-5 份真实转写稿 fixture + **人工标注的"正确答案"**（真正的高光片段区间、正确的章节边界）；跑生成器输出**命中率指标**：选段与标注的重合度、章节边界误差秒数、金句命中数；记录历史防止 prompt 越调越差 | 脚本 + `tests/fixtures/annotated/` + 历史 jsonl | 每次改 prompt 必跑 |
| 不测 | UI 样式细节、第三方 SDK 内部行为 | — | — |

**验收标准**沿用 PRD §9 的 7 条，E2E 覆盖其中可自动化的部分。
