# roughcut-stdio 实现逻辑分析与可借鉴点 v1.0

分析对象：https://github.com/Mallfurion/roughcut-stdio （local-first AI 视频粗剪工具，Python 76% + Tauri 桌面端，v2.2.1，2 stars）

## 一、它到底是什么

**面向视频剪辑师的素材筛选工具**，不是播客工具。解决的是「几十小时素材没法一条条看」：扫描整个素材文件夹 → 找出候选片段 → 打分排序 → 组装成粗剪时间线 → 导出 FCPXML 给达芬奇继续剪。

和我们的差异：它是**视频、本地运行、多素材横向筛选、输出时间线文件**；我们是**音频、云端、单文件纵向处理、输出发布物料**。所以**架构不可照搬，方法论可借鉴**——尤其是它的「选段」逻辑，正好对应我们最难也最值钱的 Story 6（出彩片段）。

## 二、它的实现逻辑（四阶段）

```
Phase 1 素材发现  → 扫描文件、匹配代理文件、探测元数据
Phase 2 逐素材分析 → 本文重点，见下
Phase 3 择优选取  → 打分、每个素材挑 1-2 个最佳片段
Phase 4 时间线组装 → 跨素材排序成粗剪
```

**Phase 2 的漏斗（核心设计）**：
```
场景检测 + 画面信号(锐度/运动/构图) + 音频信号(RMS/静音)
   ↓ 生成"种子区域"（粗糙的候选窗口）
确定性边界精修：吸附到 转录语轮/静音间隙/场景边界
   ↓
叙事单元组装：相邻片段该合并的合并（问答连续）、该拆的拆（话题突变）
   ↓
候选片段 + 质量指标（hook_strength / story_alignment / duration_fit / turn_completeness）
   ↓
仅对"边界模糊"的片段做 AI 语义校验（有预算上限）
   ↓
分层过滤：预筛选 → CLIP 语义打分 → 去重 → VLM 预算控制
   ↓
只有最强的少数片段进入昂贵的大模型分析
```

## 三、五个真正值得借鉴的设计（含我们怎么用）

### ★1 便宜信号在前，昂贵模型在后（成本漏斗）
它的核心成本控制：ffmpeg 算画面/音频信号极便宜 → 先用确定性打分砍掉大部分 → 只让少数候选进 VLM，还有全局预算百分比封顶。

**我们怎么用**：90 分钟转录稿全量喂 LLM 选段既贵又不准（长上下文中间段容易被忽略）。改成两级：
1. **确定性预筛（不花钱）**：从转录稿算出每句/每段的低成本信号——说话人切换频率（对话交锋）、语速变化、笑声/感叹词密度、静音间隔、句长突变、问答对结构
2. **LLM 精选（花钱）**：只把预筛出的 top 15-20 个候选窗口（各带上下文）喂给 LLM 排序和写理由

收益：单期 LLM 成本降一个数量级，选段质量反而更高（候选集干净）。这条直接改写我们 03/05 里「LLM 通读全稿选段」的实现方案。

### ★2 边界吸附 + 叙事单元合并/拆分（选段的"完整性"）
它不用信号峰值直接当片段边界，而是**吸附到转录语轮边界/静音间隙**，然后判断相邻片段是否属于同一个「叙事单元」（问答连续则合并、话题突变则拆分）。

**我们怎么用**：这正是切片体验的成败点——切片从半句话开始或戛然而止就废了。落地为三条规则：
- 起点吸附到「说话人开始新一轮发言」处，终点吸附到「句子结束+短静音」处
- 一问一答必须完整成对（不能只切走答案，听众不知道在回应什么）
- 引入 `turn_completeness`（语轮完整度）作为切片候选的硬指标，不完整的直接淘汰

这比我们原方案的「句边界吸附」深了一层——句边界只保证不切碎字，语轮完整才保证听得懂。

### ★3 provenance（可解释的推荐来源）
它给每个片段记录：用了哪种边界策略、置信度、来自哪个种子、是合并还是拆分来的、语义校验有没有跑——UI 上直接展示给剪辑师看。

**我们怎么用**：我们已有「AI 推荐理由」，但可以再进一步——切片卡上显示「为什么选它」的结构化标签（如：`观点交锋` `情绪峰值` `语轮完整 92%` `含 2 处金句`）。价值有二：用户更信任 AI 的判断；出问题时你自己能定位是哪层信号错了（调 prompt 时的救命稻草）。

### ★4 全链路 graceful degradation（每层不可用都有兜底）
它文档里专门一章：场景检测挂了 → 用时长启发式；CLIP 没装 → 用直方图；VLM 不可用 → 用确定性打分；音频轨缺失 → 静音默认值。**管线永远产出可用结果**。

**我们怎么用**：我们 07 文档已经覆盖了异常出路，但可以补一层「质量降级」而非「失败」的思路：
- 说话人分离失败 → 不报错，退化为无说话人标注模式，其余物料照常
- LLM 选段全部低置信 → 退化为「按信号强度给出 3 个候选 + 标注低置信」，而不是给空态

### ★5 fixture 驱动的质量回归 + benchmark 留痕
它把「片段切得对不对」做成了可评测的东西：repo 自带 fixture 集 + 评测命令，每次跑记录质量指标和运行时指标进 benchmark 历史，还按数据集指纹分组避免不同素材互相当回归基线。

**我们怎么用**：这条对我们的**简历价值最高**。我们 09 文档里的「prompt 回归测试」还只是「人工评分表」，可以升级为：
- 固定 3-5 期真实节目的转录稿 fixture + **人工标注的"正确答案"**（这几处是真正的高光、这几处该分章节）
- 每次改 prompt 跑一遍，输出命中率（选段与人工标注的重合度、章节边界误差秒数）
- 记录历史，防止 prompt 越调越差

面试时这是硬货：「我为 AI 生成质量建立了可量化的回归评测集」，比「我调了 prompt 感觉更好了」强太多。

## 四、明确不借鉴的

| 它的做法 | 为什么不适合我们 |
|----------|------------------|
| local-first / 本地跑模型 | 我们目标用户是播客主不是极客，装 Python 环境劝退；云端才有留存和数据 |
| Tauri 桌面端 | 我们 Web 优先，跨平台成本低 |
| CLIP / VLM 视觉那套 | 纯音频用不上 |
| 跨素材去重、代理文件匹配 | 我们单文件处理，无此问题 |
| FCPXML 导出 | 我们不接剪辑软件（V1.5 剪辑台也是产出成品 mp3） |
| 极其复杂的环境变量调参（20+ 个 TIMELINE_*） | 工程师工具的做法；我们面向创作者，参数要藏起来，只暴露「风格三档」 |

## 五、对我们文档的具体修改（待你确认后我改）

1. **03/05**：切片实现方案从「LLM 通读全稿选段」改为「确定性预筛 → LLM 精选 top15」两级漏斗
2. **05**：切片候选卡增加结构化推荐标签（provenance），不只是一句理由
3. **05**：切片边界规则从「句边界吸附」升级为「语轮边界吸附 + 问答成对 + 语轮完整度门槛」
4. **09**：prompt 回归测试升级为带人工标注答案的 fixture 评测集，输出命中率指标
5. **07**：补「质量降级」策略（低置信不报错，降级产出并标注）

## 六、一句话结论

这个项目和我们做的不是一件事，但它把「**如何从长素材里自动找出值得用的片段**」这件事做得比我们目前的设计深——尤其是成本漏斗、边界吸附与叙事完整性、可解释推荐、以及把选段质量变成可回归的评测集这四点。代码不能抄（无 License），思路值得抄，尤其第 1 条和第 5 条建议直接改进我们的设计。
