# Fun-ASR 接入要点与设计影响 v1.0

依据阿里云百炼非实时语音识别官方文档整理。★ = 改变了我们既有设计的硬约束。

## 一、★ 四个改变设计的硬约束

### ★1 说话人分离要求单声道，且建议 ≤2 小时
原文：「说话人分离仅支持**单声道**音频」「启用说话人分离时，建议音频时长**不超过 2 小时**，否则可能导致识别失败或超时」。

**影响**：
- 播客成品音频大量是立体声 → **必须在上传后、送 ASR 前用 ffmpeg 降为单声道**（`-ac 1`）。这是新增的必要处理步骤，不是可选优化
- 我们原定「≤3 小时」上限 → **改为 ≤2 小时**。超过 2 小时的节目 MVP 不支持（或 V1.1 做分段转写再拼接时间戳）
- 单声道转换后的文件另存，原始音频保留（用户下载用）

### ★2 敏感词过滤默认开启，会把词替换成 `*`
原文：未传 `special_word_filter` 时，系统启用内置敏感词表，匹配词被替换为等长 `*`。

**影响**：播客聊时事、聊性别、聊行业乱象都可能被打码，逐字稿出现「\*\*」会直接毁掉物料质量。**必须显式关闭系统词表**（`system_reserved_filter: false`），并在 spike 阶段验证关闭是否生效。

### ★3 结果 URL 仅 24 小时有效
原文：`transcription_url` 默认 24 小时内有效。

**影响**：任务完成后必须**立即下载 JSON 落库**，不能只存 URL。我们的 worker 要把「下载+落库」和「轮询」作为同一个原子步骤，失败要重试。

### ★4 Fun-ASR 与 Qwen3-ASR 的能力是互斥的
| 能力 | Fun-ASR | Qwen3-ASR-Flash-Filetrans |
|------|---------|---------------------------|
| 说话人分离 | ✅ | ❌ |
| 情感识别（7 类情绪标签） | ❌ | ✅ 固定开启 |
| 字级时间戳 | ✅ 固定开启 | ✅ enable_words |
| 热词 | ✅ | ❌ |

**影响**：情绪标签本来是我们切片「情绪高点」信号的理想输入，但它和说话人分离不可兼得。**MVP 决策：选 Fun-ASR**——双人对谈播客里说话人分离是刚需，情绪信号退而由 LLM 从文本判断。V1.5 可评估「Fun-ASR 全量 + Qwen3 只跑候选片段窗口拿情绪」的混合方案。

## 二、调用要点（给 Claude Code 的实现依据）

- **异步三步**：POST 提交（header `X-DashScope-Async: enable`）→ 轮询 `GET /api/v1/tasks/{task_id}`（间隔 2-5s）→ 下载 `output.results[].transcription_url` 的 JSON
- **Base URL 含 Workspace ID**：`https://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api/v1`
- **API Key 分地域**：北京 / 新加坡 / 美国的 Key 不通用。我们用**华北2（北京）**
- **必传参数**：`model: "fun-asr"`、`diarization_enabled: true`（默认关闭！不传就没有说话人）、`language_hints: ["zh","en"]`、`channel_id: [0]`
- **返回结构**：`transcripts[].sentences[]` 内含 `begin_time`/`end_time`(毫秒)/`text`/`speaker_id`/`words[]`
- **音频输入**：必须公网可访问 URL（OSS），生产环境不用本地文件上传
- **错误处理**：5xx 与超时按指数退避重试
- **降噪**：文档建议噪声大的音频先用 ffmpeg 预处理——与我们「引导用户先用 Adobe Podcast Enhance」的策略一致

## 三、★ 意外收获：热词表 = 我们的「节目设置」

Fun-ASR 支持热词表（控制台创建 → 调用时传 `vocabulary_id`），可显著提升专有名词识别率。

**这正好接上我们已有的产品设计**：节目名、常驻主播名、嘉宾名、本期主题里出现的专有名词——这些用户本来就在「节目设置」和「本期信息」里填了。可以自动合成为该节目的热词表。

**收益**：嘉宾名字、节目名不再被识别错（中文播客最常见的转写痛点之一），且**越用越准**——正好兑现我们价值主张里的「懂你」。建议：
- MVP：把节目名 + 常驻说话人 + 本期嘉宾名合成热词表（每个 show 一份，随设置更新）
- V2：把往期高频专有名词自动累积进去

这条要加进 03/05 的功能设计。

## 四、Yi 现在要做的（4 件事）

1. **确认 API Key 是「华北2（北京）」地域的**（控制台切换地域看 Key 是否一致；新加坡的 Key 调北京地址会报鉴权失败）
2. **拿 Workspace ID**：百炼控制台 → 业务空间管理，复制 Workspace ID（拼 Base URL 用）
3. **OSS bucket 建在北京地域**（`oss-cn-beijing`），与百炼同地域；读写权限私有，代码用签名 URL
4. **检查测试音频是不是立体声、时长是否 ≤2h**：
   ```
   ffprobe -v error -show_entries stream=channels,sample_rate,codec_name -show_entries format=duration your.mp3
   ```
   如果 channels=2，spike 脚本要先转单声道再上传
