# 认证邮件：已知限制 + TODO（任务 1.5）

日期：2026-07-29

## 现状

- 用的是 Supabase 免费版默认邮件服务（没接自定义 SMTP）
- **限制 1**：邮件模板不可自定义（免费版限制，要么升级付费版要么接自定义 SMTP）。默认模板是"点击登录"的魔法链接，不会显示 PRD 里说的 6 位数字验证码
- **限制 2**：默认邮件服务**每小时最多发 2 封**（项目级别，所有用户共享），实测已触发 `over_email_send_rate_limit`。这个量级连开发自测都不太够用，更不用说以后有真实用户

## 已决定的方向

Yi 决定：这两条先不处理，记 TODO，先做核心功能（上传/转写/物料生成）。

## 对当前实现的影响

- 登录用的是魔法链接（点邮件里的链接直接登录），不是输入验证码。docs/07 A1（60s 重发/连续3次提示换邮箱）和 A2（5次锁10分钟）两条策略，实现时统一映射到"同一个邮箱重复请求发信"这个计数器上（因为魔法链接场景没有"验证码输错"这个动作可对应）。见 `lib/services/auth.ts` 顶部注释
- 由于免费邮件配额限制，**没能用真实邮件走完一次完整的端到端登录测试**。用 Supabase admin 的 `generateLink` 测试过一次，发现并修复了一个真实 bug：`signInWithOtp` 必须用 `@supabase/ssr` 绑定 cookies 的 server client 调用（不能用一次性裸客户端），否则 PKCE 的 code verifier 存不进 cookie，邮件链接点回来 `/auth/callback` 换不出 session。已修复，但这个修复没能用真实邮件流程完整验证过
